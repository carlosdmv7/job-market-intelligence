# Job Market Intelligence

Public portfolio project that answers one question every morning: which open
data roles in the EU ask for my stack? Free job APIs + employers' own boards →
LLM enrichment → dbt medallion on MotherDuck → seven-page Streamlit app with a
text-to-SQL agent. uv workspace monorepo: `libs/jmi_core` (contracts, settings,
warehouse client), `scrapers`, `enrichment`, `orchestration` (Prefect flows),
`dbt/jmi`, `app`, `evals`. Map and grain of every layer: `docs/architecture.md`.

## Commands

- `uv sync --all-packages` — install every workspace member + dev tools (`make install`)
- `make check` — ruff lint + format check + mypy + pytest. Run it before saying a change is done.
- `make fmt` — auto-fix Python
- `make app` — Streamlit on :8501; with no `.env` it serves the committed demo sample
- `make pipeline ARGS="--sources ats --no-enrich"` — the daily flow once, locally
- `make ingest SOURCE=remotive [COUNTRY=de]`, `make enrich`, `make dbt-build` — single steps (need `.env`)
- `make evals` — score the classifier offline against recorded responses (what CI runs)
- dbt without cloud credentials, as CI does: `uv run python -m jmi_flows.warehouse_init`
  then `cd dbt/jmi && uv run dbt deps && uv run dbt build`, with
  `DBT_TARGET=ci DBT_DUCKDB_PATH=$PWD/jmi_ci.duckdb JMI_DUCKDB_DATABASE=$PWD/jmi_ci.duckdb`.
  `make check` does not cover dbt or evals; CI does, so run these when you touch them.

## Conventions

- Python via `uv run`, never a bare `python` / `pip`. Add a dependency to the
  member that uses it (`uv add --package jmi-app ...`). The root `pyproject.toml`
  must list every member the deployed app imports: Streamlit Community Cloud
  installs the root project.
- `requires-python` stays at `>=3.11` (ruff targets py311) while dev and CI run
  3.13. Do not raise the floor: the live app's interpreter is set in the
  Streamlit dashboard, not here.
- Ruff is the only linter and formatter; mypy covers every member.
- Code, comments and docs in English.
- Branches, commits and PRs follow `CONTRIBUTING.md`: one topic per branch from
  fresh `main` (`feat/`, `fix/`, `refactor/`, `docs/`, `ci/`, `chore/`);
  Conventional Commits (enforced by a `commit-msg` hook) whose body says *why*;
  scopes `app`, `evals`, `flows`, `dbt`, `scrapers`, `adr`; one PR per branch,
  merged with a merge commit, never squashed.
- Anything that constrains future work (a schema, a dependency, a stack choice,
  a measurement contract) gets an ADR in `docs/adr/`, with the rejected
  alternatives.
- Visual work comes from the shared `brand` package (git-pinned in
  `app/pyproject.toml`). The `[theme]` block of `.streamlit/config.toml` is
  generated by `uv run brand sync streamlit --font-prefix "Twemoji Country Flags"`
  and never hand-edited (CI fails on drift). Colours in code come from
  `brand.tokens`, never a hardcoded hex. No CSS injection: native theme keys only.
- The app must keep working with no secrets: it falls back to `app/demo/*.parquet`
  and says so on every page. Regenerate the sample with `make demo-data`.
- After a prompt or model change: `make evals-live` to see what moved, then
  re-record (`make evals-record`) and commit the fixtures. Bump the enrichment
  `prompt_version` (a bump means re-enrich). `evals/thresholds.json` is the
  committed quality floor; never lower it to make CI pass.
- Verify app changes by running them (`make app` in the browser), not only by tests.

## Domain rules (do not break)

- **Absence is never a finding.** A posting the LLM has not read says "not yet
  classified" everywhere, never "no match".
- **A filled role is not an open one.** `is_active` is measured against the
  corpus's newest observation, not `current_date`. Closed roles stay in the
  trends and are excluded from every list.
- **Facts that can be looked up are never inferred** (ADR 0007, 0011): use the
  authoritative source and show the receipt (e.g. the IND register with its
  KvK number). The LLM is for what only exists as prose.
- Batched enrichment matches each response by the posting index it echoes,
  never by position.
- "Is this a data role?" has one definition, `jmi_core.roles`, mirrored by the
  dbt macro `jmi_is_target_role`; `scrapers/tests/test_target_role_parity.py`
  keeps them in step. Change both or neither.
- Pydantic v2 contracts in `jmi_core` are the source of truth; `warehouse/ddl/`
  mirrors them by hand. Bump `SCHEMA_VERSION` on any breaking change to either.
- `raw.*` is append-only. `content_hash` is computed in `jmi_core` and
  re-derivable in dbt; `canonical_job_id` is assigned only in dbt `int_`, never in raw.
- raw/staging names are snake_case; marts are `FT_` / `DT_`.
  `staging.stg_job_postings` is at observation grain: joined to the marts on
  `content_hash`, a posting fans out once per sighting.
- Source depth differs (an Adzuna teaser vs a full JobTech ad), so anything
  aggregated per country carries that caveat (ADR 0011).

## Security and cost (hard rules)

- The repo is **public**. Nothing secret in git: `.env` is ignored; deployed
  secrets live in the Streamlit and GitHub dashboards.
- The app is read-only **by connection** (ADR 0009): `read_only=True`, enforced
  by MotherDuck. Never add a fallback to a writable connection; if read-only
  fails, drop to the demo sample.
- The text-to-SQL agent has three independent layers (ADR 0012): DuckDB parses
  the query and allows only the marts tables; the connection is read-only with
  file and network access off and its configuration locked; results time out
  and are withheld if they carry a credential. Never weaken one layer because
  another would catch it. `app/tests/test_security.py` covers them.
- Runs at 0 € (ADR 0005, 0008): Gemini free tier (20 requests/day/model,
  shared by enrichment and the app's `JMI_APP_LLM_CALLS_PER_DAY`), MotherDuck
  free tier, GitHub Actions as the scheduler. A paid service or a new quota
  consumer needs an ADR first.
